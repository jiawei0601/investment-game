# /複盤 — 戰報複盤協調器

此 skill 不自行扮演任何大師人格，是協調層：定位戰報 → 依序觸發三個既有 user-level
perspective skill → 依固定分工彙整評語 → 給跨局總結。三位大師的人格與語氣一律由
各自的 perspective skill 決定，本檔只規定「該讀哪些區塊、該評什麼、不該評什麼」。

## 範圍聲明（刻意排除，非遺漏）

本 skill v1 只召集 Livermore、OPMAN、謝孟恭三位。以下為刻意排除，需在複盤輸出開頭
一併說明：

- **Dalio**：SPEC.md §6 明訂退居選配，不在 v1 預設呼叫範圍。
- **Buffett／Graham／Lynch**：價值投資／選股邏輯與台指期貨這個商品無關，不上。
- **林沖**：現股當沖框架，留給未來現股當沖版使用，不適用於本遊戲的台指期貨商品。
- **OPMAN 的評語範圍限制**：本版遊戲無選擇權鏈資料（ADR 0007 後果段），OPMAN 評語
  限於「大盤格局判讀／資金控管／紀律」層面，不評選擇權履約價、Greeks 或賣方策略；
  選擇權相關洞見留待第二版。

## 步驟 1：定位戰報

- **搜尋位置（依序）**：① repo `reports/*.md`；② 使用者的 FSA 存檔資料夾
  `C:\Users\chang\OneDrive\Documents\期貨練習\reports\*.md`（玩家在遊戲內授權的
  實際存檔位置，profile.json 也在該資料夾）。兩處都掃，同名以較新者為準。
- **無參數**：掃描上述位置的 `*.md`，依檔名 `{levelId}-{attempt}-{date}.md` 的
  `{date}`（YYYY-MM-DD）取最新一份；同日多筆再比 `{attempt}` 取最大值。
- **有參數**：
  - 參數看起來是檔名（含 `.md` 或符合 `{levelId}-{attempt}-{date}` 樣式）→ 直接比對
    `reports/` 下的檔案（可省略 `.md` 副檔名、可省略 `reports/` 前綴）。
  - 參數是關卡名（例如 `pandemic`）→ 比對檔名開頭 `{levelId}-` 的所有戰報，若唯一
    命中直接用；若命中多筆（同關卡玩過多次），列出這幾筆（含第幾次玩、日期區間，
    可從戰報「## 1. 標頭」讀取）請使用者指定要哪一筆。
- **找不到**（無參數但 `reports/` 是空的；或有參數但比對不到任何檔案）：列出
  `reports/` 目錄下現有的所有戰報檔名，請使用者從中選一份，不要自行臆測或編造內容。

## 步驟 2：讀取脈絡

- 讀取選定戰報 `.md` 全文。
- 讀取 repo 根目錄的 `profile.json`（跨局歷史，schema 見 `src/behavior/profile.js`）；
  若檔案不存在或無法解析，視為「第一局」，如實告知使用者，不要臆測歷史資料。
- 戰報本身「## 7. 歷次對照」區塊已經是 `buildReport()` 用 `profileHistory` 算好的
  跨局曲線與「連續 N 局未改善」清單，步驟 4 直接讀這個區塊即可，不需要自己重算。

## 步驟 3：三位大師固定分工

戰報固定 8 個 heading（見 `src/report/report.js` 檔頭 schema、`tests/report.test.js`）：
`## 1. 標頭`、`## 2. 開局作戰計畫`、`## 3. 逐筆交易時間軸`、`## 4. 保證金壓力軌跡`、
`## 5. 違背統計`、`## 6. 行為分`、`## 7. 歷次對照`、`## 8. 複盤指引`。

三位大師的評論範圍與對應戰報區塊**明確寫死如下，不得越界評論**：

| 大師 | 只評 | 讀哪幾節 | 對應違背類型（`## 5.`／`## 6.`） |
|---|---|---|---|
| **Livermore** | 停損執行與趨勢紀律：戰報的凹單／凹單持續、停損觸價（`## 2.` 的停損規則設定）vs 實際平倉時點（`## 3.` 的「停損觸發平倉」列與時間差） | `## 2.`（停損規則欄位）、`## 3.`（⚠ 凹單／⚠ 凹單持續 標記列、停損觸發平倉 vs 平倉的時間差） | `bag_holding`、`bag_holding_continued` |
| **OPMAN** | 資金控管與凹單：保證金使用率軌跡、追繳／強平事件、口數紀律（十筆單精神——單筆是否重壓） | `## 2.`（保證金使用率上限設定）、`## 4.`（使用率峰值／最大回撤／逐日摘要／追繳與強平事件表）、`## 3.`（口數欄位） | `risk_out_of_control`、`martingale_add` |
| **謝孟恭** | 部位管理與心態：計畫外交易、論點漂移、違背的重複模式 | `## 2.`（開局計畫 vs 實際）、`## 3.`（論點欄位，比對同一部位前後論點是否一致、⚠ 計畫外交易 標記）、`## 7.`（歷次對照，找重複模式） | `unplanned_trade`、`thesis_drift` |

## 步驟 4：依序召集三位大師

對每一位大師，**依序**（不要跳過、不要合併）：

1. 用 Skill 工具觸發對應的 user-level perspective skill（`livermore-perspective`／
   `opman-perspective`／`gooaye-perspective`），並在觸發時附上步驟 3 表格中該大師
   該讀的戰報節錄（原文引用，不要摘要改寫再餵給對方，避免失真）。**必須先觸發，
   再產出評語**——不要用自己的話模仿語氣代替真的呼叫該 skill。
2. 用該 skill 激活後的人格與語氣，依下列固定結構寫一段評語（三點都要有，不可省略
   任一點）：
   1. **這局最該罵的一件事**：從步驟 3 指定的節錄中引用具體行號／事件（日期＋
      商品＋動作，例如「2020-03-03 開倉 空 …」或「使用率峰值 87.3%（2020-03-05）」），
      不接受空泛描述。
   2. **有進步的一件事**：對照「## 7. 歷次對照」裡該大師負責的違背類型次數演變，
      若本局比前幾局有改善（次數下降或掉到 0）才寫；若本局是第一局（歷史不足）或
      該類型從未改善，誠實說「目前看不到進步」或「基線剛建立，尚無對照」，不要硬
      湊一件事出來。
   3. **下一局只改一件事**：具體、單一、可執行的建議，不要開清單。

**禁止事項（三位皆適用）**：
- 禁止空泛讚美（例如「操作得不錯」「整體表現尚可」這類無具體引用的話）。
- 禁止評論報酬率高低——戰報「## 1. 標頭」的報酬率只是事實陳述，不參與行為分
  （SPEC.md §3、ADR 0003），三位大師的評語不得引用或評價這行數字。
- 禁止越界評論其他大師負責的違背類型統計數字（`## 5.`／`## 6.` 裡屬於別人那幾類的
  次數與明細，見步驟 3 表格最後一欄）。同一筆交易本來就可能被多個角度討論——例如
  同一筆加碼，OPMAN 談資金曝險與口數，謝孟恭談論點文字裡的自我察覺——只要各自扣住
  自己的鏡頭（資金控管 vs 心態）即可，不必迴避同一筆交易紀錄。

## 步驟 5：跨局總結

三位大師發言完畢後，另外寫一段跨局總結（不掛在任何一位大師名下，用複盤協調者
自己的口吻）：

- 讀戰報「## 7. 歷次對照」的「### 連續 N 局未改善」子節。
- 若有項目：一句話點名（例如「連續 3 局『攤平加碼』都沒改掉，是這幾局最頑固的
  問題」）。
- 若該子節顯示「資料不足」（第一局或歷史不足 N 局）：明確說明「這是基線局，
  跨局比較要等累積到 N 局才看得出來」，不要臆測趨勢。

## 步驟 6：固定收尾提醒

複盤輸出最後固定附上一句（逐字或語意相同即可，不可省略）：

> 以上評語基於本局行為紀錄（違背類型、保證金軌跡、逐筆交易時間軸），不是投資建議，
> 不構成任何買賣或部位判斷的依據。
