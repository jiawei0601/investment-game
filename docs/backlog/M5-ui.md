# M5 UI

## 目標

K線圖顯示（lightweight-charts）＋籌碼副圖、時間推進控制（按日推進）、日內回放（點開任一日觀看生成日內路徑）、三商品（大台/小台/微台）下單面板。把 M2-M4 的邏輯層接上可玩的介面。

## 依賴

M2（日K與日內資料）＋ M3（保證金引擎結果需要顯示）＋ M4（作戰計畫表單需要 UI 呈現）。

## 驗收條件

- [ ] K線圖使用 lightweight-charts 渲染真實日K層資料，可正確顯示 OHLC
- [ ] 籌碼副圖：顯示期貨三大法人（外資/投信/自營）多空淨部位，與主圖日期軸同步
- [ ] 時間推進按日推進，一天一根日K；推進一律不可逆：UI 上沒有「回上一步」控制，邏輯層也需防止倒退（可用 code review 或測試確認狀態機沒有倒退 API）
- [ ] 日內回放：玩家可點開任一已推進過的日期，觀看該日生成日內路徑（M2 產出），純顯示用途之外，回放時需清楚標示「觸價判定已在推進時完成」，不可讓玩家誤以為回放畫面能重新觸發交易
- [ ] 三商品下單面板：可同時顯示大台/小台/微台的口數輸入與保證金試算，下單前顯示所需保證金與目前可用資金
- [ ] 結算日（每月第三個週三）UI 明確提示轉倉或平倉選擇，不可讓玩家在不知情下被動轉倉
- [ ] 可完整跑完一次劇本關卡（疫情／熊市／平淡／閃崩任一關）的端到端流程（手動操作或自動化流程皆可）
- [ ] 純靜態網頁：整包在無建置步驟下開啟 `index.html` 可執行（驗證方式：不需要 `npm run build`，直接開檔案或起最簡靜態伺服器即可玩）

## 建議派工模型

`sonnet`，或指定 Frontend Developer agent。圖表串接與互動邏輯建議由 `sonnet` 實作後，搭配 Browser pane 工具做人工瀏覽器驗證（確認圖表渲染、推進控制、日內回放、三商品下單面板符合預期），不建議只憑程式碼審查判斷 UI 是否可用。
