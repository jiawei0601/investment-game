# M5 UI

## 目標

K線圖顯示（lightweight-charts）、時間推進控制（預設週推進、事件日自動降速到日）、日內視覺層（點開單日才 lazy 生成，僅顯示不參與成交）。把 M2-M4 的邏輯層接上可玩的介面。

## 依賴

M2（日K資料）＋ M3（撮合結果需要顯示）＋ M4（作戰計畫表單需要 UI 呈現）。

## 驗收條件

- [ ] K線圖使用 lightweight-charts 渲染日K層資料，可正確顯示 OHLC
- [ ] 時間推進預設以週為單位；事件日（單日振幅超閾值、持股財報日、FOMC 決議日，需在程式碼中明確定義判定規則）自動降速為逐日推進，有測試驗證降速邏輯正確觸發
- [ ] 時間推進一律不可逆：UI 上沒有「回上一步」控制，邏輯層也需防止倒退（可用 code review 或測試確認狀態機沒有倒退 API）
- [ ] 日內視覺層：僅在玩家點開某日時才 lazy 生成，同 seed 下重複開啟同一天顯示結果一致
- [ ] 日內視覺層的資料流向與撮合／停損判定模組物理隔離（此條與 M3 驗收條件互相印證，可共用同一組測試或 code review 檢查）
- [ ] 可完整跑完一次劇本關卡（疫情／熊市／平淡／AI 任一關）的端到端流程（手動操作或自動化流程皆可）
- [ ] 純靜態網頁：整包在無建置步驟下開啟 `index.html` 可執行（驗證方式：不需要 `npm run build`，直接開檔案或起最簡靜態伺服器即可玩）

## 建議派工模型

`sonnet`，或指定 Frontend Developer agent。圖表串接與互動邏輯建議由 `sonnet` 實作後，搭配 Browser pane 工具做人工瀏覽器驗證（確認圖表渲染、推進控制、日內視覺層點擊行為符合預期），不建議只憑程式碼審查判斷 UI 是否可用。
