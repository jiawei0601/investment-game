# M1 資料管線

## 目標

抓取 44 檔美股月K真實資料＋FRED 總經資料，並手工補齊地雷股（含已下市標的）的完整月K，輸出為靜態 JSON，供 M2 生成引擎與後續所有模組使用。這是整個資料鏈最上游，沒有它其他里程碑無法開工。

## 依賴

無。可立即開工（與 M6 並列可先行項目）。

## 驗收條件

- [ ] `data/monthly/` 下存在對應 44 檔標的的 JSON 檔案，檔名可明確對應 ticker（如 `SPY.json`）
- [ ] 有一份標的清單檔（如 `data/tickers.json`）列出全部 44 檔，並依 SPEC §5 六層分類標註：指數/資產 ETF（~9）、槓桿/反向（~4）、大型權值（~15）、高波動題材（~8）、地雷股（~6）、加密（2）
- [ ] 每檔月K資料從 2010-01 起（尚未上市者從其上市月起，需標注 `listed_date`）到目前為止，月份序列連續無缺月——需寫一支驗證腳本跑過全部 44 檔並輸出通過/失敗清單
- [ ] 地雷股（Hertz、Bed Bath & Beyond、SVB、Peloton、Zoom/Teladoc 類，共 ~6 檔）含**下市前完整月K數據**，並標注 `delisted_date` 與下市原因（破產/收購/下櫃）
- [ ] 每檔 JSON schema 一致，至少含 `date, open, high, low, close, volume`，並有文件（可寫在 `data/README.md` 或 `tools/README.md`）說明 schema
- [ ] `data/macro.json` 存在，含 FRED 利率、CPI、失業率、殖利率曲線，時間範圍涵蓋 2010-01 至今
- [ ] 常規標的（非地雷股）的抓取腳本存於 `tools/`（Python），可重跑更新至最新月份
- [ ] 地雷股資料來源與取得方式（人工蒐集管道、如何驗證下市日與最後成交價正確性）有文字記錄，不能只有資料沒有來源說明——這批資料出錯會直接污染 SPEC §9-3 的防呆核心

## 建議派工模型

- 常規 38 檔＋FRED 抓取：`sonnet`（標準 API 串接＋資料清洗，邏輯不複雜但要處理資料缺口判斷）。
- 地雷股 ~6 檔的歷史資料蒐集與下市日/最後價格核實：不建議完全自動化，建議 `sonnet` 負責搜尋與初步整理，人工（使用者）複核關鍵數字（下市日、最後成交價）後再定案，因為這批資料錯了會直接打壞 ADR 0004 的防呆效果。
