# M1 資料管線

## 目標

抓取台指期（TX）近月連續日K真實資料＋期貨三大法人籌碼＋台美總經資料，輸出為靜態 JSON，供 M2 生成引擎與後續所有模組使用。這是整個資料鏈最上游，沒有它其他里程碑無法開工。

## 依賴

無。可立即開工（與 M6 並列可先行項目）。

## 驗收條件

- [ ] `data/daily/TX.json` 存在，內容為台指期近月連續（TX 日盤）2010-01 至今真實日K OHLC＋成交量，來源 FinMind `TaiwanFuturesDaily`
- [ ] 日K序列對照台股交易日曆（含颱風假等臨時休市）無缺日；需寫一支驗證腳本跑過全部日期並輸出「應交易日 vs 實際資料日」的差異清單，缺日需在驗收時逐筆列出並確認原因（休市 / 資料源缺漏）
- [ ] OHLC 合法性檢查：每日須滿足 `L ≤ O,C ≤ H` 且四值皆為正數，違反者輸出清單供人工核對
- [ ] 只納入日盤（08:45-13:45）資料，不納入盤後交易時段（ADR 0007）；需在抓取腳本或文件中明確標注篩選邏輯
- [ ] 連續近月轉倉規則有文字記錄：資料如何在近月合約到期前後銜接（沿用 FinMind 資料集本身的連續近月欄位，或自行處理轉倉價差），需說明依據
- [ ] `data/chips.json` 存在，含期貨三大法人（外資/投信/自營）多空淨部位，來源 FinMind `TaiwanFuturesInstitutionalInvestors`，時間範圍涵蓋 2010-01 至今且與 `TX.json` 日期範圍一致
- [ ] `data/macro.json` 存在，含台灣總經（央行重貼現率、CPI、失業率，FinMind 台灣總經數據集）＋美國總經（聯邦基金利率，FRED `fredgraph.csv` 免金鑰），時間範圍涵蓋 2010-01 至今
- [ ] JSON schema 一致且有文件說明（可寫在 `data/README.md` 或 `tools/README.md`）：`TX.json` 至少含 `date, open, high, low, close, volume`；`chips.json` 至少含 `date, 外資淨部位, 投信淨部位, 自營淨部位`
- [ ] 抓取腳本存於 `tools/`（Python），可重跑更新至最新交易日

## 建議派工模型

`sonnet`。FinMind API 串接與台股交易日曆核對邏輯明確，屬標準資料清洗工作，不需要創造性設計。日K缺日核對建議實作後由使用者抽查交易日曆比對結果，確保不是驗證腳本本身的邏輯錯誤掩蓋了真實缺口。
