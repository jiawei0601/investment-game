# M4 行為系統

## 目標

實作開局作戰計畫表單、規則式矛盾偵測、五類違背的機器全程比對、以及行為分（D）計算。這是整個訓練工具的核心診斷邏輯（SPEC §3、ADR 0003 修訂版）。

## 依賴

M3（違背偵測需要保證金引擎產生的交易與強平事件流作為比對依據）。

## 驗收條件

- [ ] 開局作戰計畫表單涵蓋 SPEC §3 六項全部選項（目標／最大回撤／停損規則／加碼規則／保證金使用率上限／持倉過夜），選項值需完整對應 SPEC 列出的每一個選項（不可少列或改動選項文字）
- [ ] 論點欄：每次新開倉（含反手）時強制詢問「一句話：為什麼是現在、為什麼是這個方向？」，並將論點文字與該筆倉位綁定儲存
- [ ] 矛盾偵測至少涵蓋 SPEC §3 列出的兩組範例，各有對應測試案例觸發預寫模板攔阻：
  - 「逆勢攤平」＋「回撤 10%」
  - 「保證金使用率 70%+」＋「回撤 10%」
  - 「當日沖銷為主」＋「停損＝論點失效才走」
- [ ] 矛盾偵測為純規則實作，程式碼中不出現任何 LLM/外部 API 呼叫（可用 grep 檢查 import 與網路呼叫）
- [ ] 不矛盾的合法計畫組合可零摩擦直接開局，需有測試驗證合法組合不被誤攔（避免規則過寬誤傷）
- [ ] 五種違背類型（凹單／計畫外交易／風險失控／論點漂移／攤平加碼）皆有機器比對邏輯，各至少一個觸發案例＋一個不觸發案例的單元測試：
  - 凹單：觸停損未平
  - 計畫外交易：含無理由過夜、超口數
  - 風險失控：回撤或保證金使用率超計畫
  - 論點漂移：因價格而非論點改變方向
  - 攤平加碼：計畫外的逆勢加碼
- [ ] 行為分（D）計算邏輯獨立於報酬率：需有測試驗證「報酬率不同但行為完全一致的兩次模擬得到相同 D 分數」
- [ ] `profile.json` schema 定案，可記錄跨局行為分與各違背類型次數，供 M7 讀寫使用

## 建議派工模型

`sonnet`。規則引擎與比對邏輯明確，`sonnet` 足以勝任。矛盾偵測模板的文字語氣（大師噴人的口吻）建議讓指揮官本人或 `fable` 過一輪，確保符合角色設定；但這只是文案潤飾，不影響邏輯實作分派。
