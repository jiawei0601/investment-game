# M6 事件卡管線

## 目標

每月 2-3 張、共約 600 張事件卡，透過 LLM（DeepSeek 管線）一次性預生成，通過嚴格檢查工序後存為靜態 JSON 進 repo。可與 M2-M5 並行開發。

## 依賴

無強依賴，可與 M1 並列優先開工。需要 M1 的標的清單以確保事件卡能正確對應到標的，但事件卡生成本身（時間軸＋總經框架）不依賴生成引擎（M2）。

## 驗收條件

- [ ] `data/events/` 下存在事件卡資料，數量依「每月 2-3 張 × 涵蓋所有劇本關卡時間範圍 + 無限模式所需總月數」實際計算得出（約 600 張，需在文件中列出計算依據與涵蓋月份範圍）
- [ ] 每張事件卡皆為「當時口吻」，例：「亞洲某些工廠傳出停工，影響尚待評估」；**嚴禁**「這是史上最快熊市的開端」這類後見之明措辭
- [ ] 有明確的關鍵詞黑名單（至少含「開端」「史上最大」「隨後」「事後證明」等，需列出完整清單於 `tools/` 或 `docs/` 下），所有事件卡皆過一輪黑名單比對，含黑名單詞者判定不通過
- [ ] 黑名單機器比對之外，額外跑一輪 LLM 複審（需記錄複審 prompt 與判定邏輯），複審未過者重生成；生成與複審 log 需可追溯（存檔或版本紀錄）
- [ ] 事件卡 JSON schema 統一，至少含日期、關聯標的（可為空，代表總經事件）、內容文字、分類，並有文件說明
- [ ] 抽樣至少 30 張人工複核，確認無漏網後見之明措辭，複核結果需記錄（誰核的、核了幾張、有無打回重生成）
- [ ] 事件卡生成管線程式碼存於 `tools/`，可重跑增補或針對特定月份重新生成

## 建議派工模型

生成本身依「額度節約」原則優先走免額度管道（DeepSeek 官方 API 或 NIM 腳本，非 Claude agent 額度）；黑名單機器複審可用 `haiku` 或純腳本完成；LLM 複審一輪與最終 30 張人工抽樣複核建議 `sonnet` 或使用者親自把關——SPEC 明訂「一張漏餡的卡毀掉一整關」，這是全流程中容錯率最低的一環，不建議完全交給低階模型自動放行。
