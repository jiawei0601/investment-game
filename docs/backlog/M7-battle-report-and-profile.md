# M7 戰報與檔案

## 目標

結算時輸出戰報 `.md`（開局計畫、逐筆交易與違背標記、違背統計、歷次對照曲線）到 `reports/`，並持久化 `profile.json`，呈現跨局進步曲線。

## 依賴

M4（行為分／違背資料）＋ M3（交易紀錄）＋ File System Access API 落地（ADR 0006 定案的機制，需在此里程碑實際串接）。

## 驗收條件

- [ ] 結算後自動透過 File System Access API 寫入 `reports/{時間戳或關卡ID}.md`，無需玩家手動另存
- [ ] 戰報 `.md` 內容完整包含：開局作戰計畫、逐筆交易列表（每筆標註是否觸發違背及違背類型）、四類違背統計次數、與歷次紀錄的對照曲線（文字表格或簡易呈現皆可）
- [ ] `profile.json` 正確累積跨局行為分歷史與各違背類型次數，格式需可被 M8 的 `/複盤` skill 直接解析（不需臆測格式）
- [ ] 劇本模式中離作廢不寫入 `profile.json`：需有測試驗證中離情境不計入跨局曲線（對應 SPEC §9-4 的無中途存檔互鎖）
- [ ] 檔案寫入為使用者一次性授權後自動進行，之後操作不需重複跳出授權視窗（需手動或自動化驗證瀏覽器行為，限 Chrome/Edge 環境）
- [ ] 戰報 `.md` 有明確 schema 文件，供 M8 開發時不需臆測欄位或格式

## 建議派工模型

`sonnet`。檔案輸出格式與 File System Access API 串接邏輯明確，不需要高階模型；若對 File System Access API 的瀏覽器行為（授權持久化範圍、跨頁面重新整理後是否需要重新授權）把握不大，建議先花一輪做小範圍 spike 驗證 API 行為，再進入正式實作。
