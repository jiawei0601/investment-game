# M3 撮合與帳務

## 目標

實作買賣撮合、交易成本、現金流（含整局最多一次重大衝擊事件）、帳務結算，全部成交判定只認 M2 產出的日K層資料。

## 依賴

M2（需要日K生成引擎提供成交判定用的真相層資料）。

## 驗收條件

- [ ] 買 / 賣 / 停損觸發皆以日K層（非日內視覺層）為判定依據；需有測試證明撮合模組不讀取、不呼叫日內視覺層的任何資料或函數（互鎖見 SPEC §9-5、ADR 0002）
- [ ] 交易成本模型：美股比照 SPEC §4 為零手續費但含價差，需定義具體價差模型（如 bid-ask spread 假設值或公式）並在測試中驗證扣除金額正確；台股模型（0.1425% 手續費 + 0.3% 證交稅）可先建好介面但 v1 不啟用，需在程式碼與文件中明確標注「v2 功能」
- [ ] 現金流：每月固定投入金額（模擬薪水）正確累加進帳戶，有單元測試
- [ ] 整局最多觸發一次重大衝擊事件（如「兩週內必須提出 30 萬」），需有測試驗證同一局不會觸發第二次
- [ ] 衝擊事件觸發時機「偏好帳面虧損最大時」需有具體規則實作（例如虧損幅度越大、觸發機率權重越高的加權抽樣），並有測試驗證此偏好方向成立（而非均勻隨機觸發）
- [ ] 強迫賣出時記錄「賣出的是帳面賺錢還是賠錢的部位」，作為處分效應診斷資料，供 M4 行為系統讀取
- [ ] 起始資金為玩家開局輸入的真實金額量級，帳務計算以此為基礎，不可用固定假資金覆蓋玩家輸入
- [ ] 全部帳務邏輯有獨立單元測試，不需要 UI 即可跑

## 建議派工模型

`sonnet`。撮合與帳務邏輯規則明確、無需創造性設計，適合直接實作；衝擊事件的加權抽樣規則若涉及數值調參，實作後建議跑一輪模擬統計觸發分佈是否符合預期（可交給同一個 `sonnet` 一併完成，不需升級模型）。
