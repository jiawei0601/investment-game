# M2 生成引擎

## 目標

實作布朗橋日K生成器＋共同市場因子＋種子系統，把 M1 的真實月K骨架轉換為確定性生成的日K（遊戲成交真相層）。這是 ADR 0002 定案的機制，也是 B2 後見之明對策（ADR 0003）能成立的地基。

## 依賴

M1（需要真實月K資料作為布朗橋錨點的輸入）。

## 驗收條件

- [ ] 種子函數為純函數：`seed = hash(關卡ID, 第幾次玩, 標的, 年月)`，同輸入必產生同輸出，有單元測試覆蓋
- [ ] 給定同一種子，重複呼叫生成引擎兩次，輸出日K序列完全一致（確定性測試）
- [ ] 生成日K的月聚合（月初開盤 / 月末收盤 / 月內最高 / 月內最低）需精確還原對應月K的真實 OHLC：O/C 需 exact match，H/L 需 exact match（允許浮點誤差界內，如 1e-6）
- [ ] 由生成日K反推的 Parkinson 波動率 `σ ≈ ln(H/L)/(2√ln2)`，與由真實月K H/L 算出的目標 σ，誤差落在明訂容忍界內（需在測試中明確定義容忍百分比，例如 ±5%，或改用統計顯著性檢定）
- [ ] 布朗橋於 log 價格空間執行，兩端錨死 `log(O)→log(C)`（單元測試驗證起訖點）
- [ ] H、L 落點與順序隨機決定，月份切三段各自跑一次布朗橋；具備拒絕採樣（越界路徑重試）與超過重試上限後 clip 的 fallback 機制，兩者皆有測試覆蓋（可用極端波動率參數強制觸發 clip 分支）
- [ ] 共同市場因子：對同一月份多個標的生成日K時，不同標的間的日報酬存在因子驅動之相關性（可用統計檢定：跨標的殘差相關係數顯著大於 0，且方向與各自 beta 一致），需有測試明確排除「各標的獨立隨機」的錯誤實作
- [ ] 生成引擎為純函數／無副作用，程式碼中不出現 `Date.now()` 或 `Math.random()` 直接呼叫於遊戲邏輯（可用 grep/lint 規則驗證）
- [ ] 有可獨立執行的測試套件，不依賴 UI，可用單一指令跑完（如 `npm test` 或等同）

## 建議派工模型

`sonnet`。統計與隨機過程邏輯（布朗橋、拒絕採樣、共同因子模型）比一般 CRUD 複雜，若對共同因子模型的設計把握不大，可先請 `opus` 或指揮官本人過一輪設計 review（模型形式：市場因子 + beta + 特異噪音如何具體參數化），設計定案後實作交給 `sonnet` 即可，不需要全程用高階模型。
