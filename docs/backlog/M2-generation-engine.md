# M2 生成引擎

## 目標

實作布朗橋日內 5 分K生成器＋種子系統，把 M1 的真實日K骨架轉換為確定性生成的日內路徑（遊戲成交真相層：觸價、強平判定皆以此為準）。這是 ADR 0002（修訂版，見 ADR 0007）定案的機制，也是 B2 後見之明對策（ADR 0003）能成立的地基。

## 依賴

M1（需要真實日K資料作為布朗橋錨點的輸入）。

## 驗收條件

- [ ] 種子函數為純函數：`seed = hash(關卡ID, 第幾次玩, 日期)`，同輸入必產生同輸出，有單元測試覆蓋
- [ ] 給定同一種子，重複呼叫生成引擎兩次，輸出日內 5 分K序列（60 根，日盤 08:45-13:45）完全一致（確定性測試，對應 AGENTS.md 測試慣例第三項）
- [ ] 生成日內路徑的**聚合須還原當日真實 OHLC**：開盤＝第一根開盤、收盤＝最後一根收盤、路徑最高/最低須與真實日K的 H/L exact match（允許浮點誤差界內，如 1e-6）（對應 AGENTS.md 測試慣例第一項）
- [ ] 生成日內路徑的**極值須還原當日真實 H/L**：由生成路徑反推的 Parkinson 波動率 `σ ≈ ln(H/L)/(2√ln2)`，與由真實日K H/L 算出的目標 σ 一致（誤差需落在明訂容忍界內，需在測試中明確定義容忍百分比，例如 ±5%）（對應 AGENTS.md 測試慣例第二項）
- [ ] 布朗橋於 log 價格空間執行，兩端錨死 `log(當日O)→log(當日C)`（單元測試驗證起訖點）
- [ ] H、L 落點與順序隨機決定，當日切三段各自跑一次布朗橋；具備拒絕採樣（越界路徑重試）與超過重試上限後 clip 的 fallback 機制，兩者皆有測試覆蓋（可用極端波動率參數強制觸發 clip 分支）
- [ ] 單一標的（台指），不含任何跨標的相關性模型（ADR 0002 修訂版：共同市場因子機制已移除，見 ADR 0007）
- [ ] 生成引擎為純函數／無副作用，程式碼中不出現 `Date.now()` 或 `Math.random()` 直接呼叫於遊戲邏輯（可用 grep/lint 規則驗證）
- [ ] 有可獨立執行的測試套件，不依賴 UI，可用單一指令跑完（如 `npm test` 或等同）

## 建議派工模型

`sonnet`。統計與隨機過程邏輯（布朗橋、拒絕採樣）比一般 CRUD 複雜，但單一標的下不再需要共同因子模型設計，複雜度低於 v1.0 版本，`sonnet` 可直接實作，不需要額外的 `opus` 設計 review。
