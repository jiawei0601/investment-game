# 2. 月K真實骨架＋種子化布朗橋生成日K

狀態：已採納

## 脈絡

遊戲需要「重玩同一關但結果不同」的機制（見 ADR 0003 的 B2 後見之明對策）：月K骨架不變（玩家知道方向），日K全部重擲（玩家不知道執行細節）。若日K直接用真實歷史資料，重玩就等於背答案，行為分整套失效（SPEC §9-1）。同時免費資料來源沒有乾淨的分鐘級歷史，且就算有，直接顯示真實分鐘走勢也會被拿來當成交依據，與「重擲」機制衝突。

另外遊戲需要可重現性（reload、重看同一天走勢要一致）與可測試性（生成引擎不能是黑箱亂數）。

## 決策

採三層資料架構（SPEC §1）：

1. **月K骨架（真實）**：2010-01 至今真實月K OHLC（yfinance/stooq 抓取），一次性存 `data/monthly/*.json`，是唯一的真實資料層。
2. **日K層（生成，遊戲真相層）**：布朗橋在 log 價格空間生成，兩端錨死 `log(O)→log(C)`；波動率用 Parkinson 估計 `σ ≈ ln(H/L)/(2√ln2)` 反推；隨機決定 H、L 落在月內哪兩天（順序隨機），月份切三段各跑一次布朗橋；越界路徑拒絕採樣重試，超過重試上限則 clip。多標的間不可獨立隨機——由單一共同市場因子＋各自 beta＋特異噪音組成日內殘差，避免同一天盤面出現「各股各走各的」的假象。
   種子 = `hash(關卡ID, 第幾次玩, 標的, 年月)`，純函數。所有成交、停損、結算只認這一層。
3. **日內視覺層（生成，純顯示）**：點開某日才 lazy 生成分鐘級走勢，錨住當日 OHLC，同 seed 保證重看一致，但**不參與任何成交判定**（互鎖見 SPEC §9-5 / ADR 0003）。

## 後果

- 換來確定性重玩：同種子兩次生成結果完全一致，是 B2 對策與統計測試（M2）成立的前提。
- 換來可測試性：種子函數為純函數，日K月聚合可反推驗證是否還原真實月K OHLC，Parkinson 波動率誤差可設界檢驗。
- 代價：生成的日K不是真實市場微結構，只是統計性質相似（月OHLC還原、波動率吻合），不能對外宣稱「重現歷史某天真實走勢」。
- 代價：拒絕採樣＋clip fallback 增加實作複雜度，且 clip 觸發時的路徑品質是妥協，需要監控觸發頻率是否異常偏高。
- 代價：日內視覺層是完全虛構的資料，一旦有人（未來的自己或另一個 agent）為了「順手」把它接進撮合邏輯，就會讓玩家被不存在的價格停損出場——這是 SPEC §9-5 明訂的互鎖，本 ADR 重申：日內視覺層與日K層必須維持程式碼層級的隔離（不同模組、不共用同一組「取當前成交價」的函數）。
- 代價：共同市場因子模型本身是簡化假設，不是真實的跨資產相關性估計，只保證「不會出現各股獨立亂走」的最低限度真實感，不追求相關係數精確重現史實。
