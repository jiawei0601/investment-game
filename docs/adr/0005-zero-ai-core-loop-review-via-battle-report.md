# 5. 遊戲本體零 AI 依賴、複盤走戰報 .md 回 Claude Code

狀態：已修訂（見 0007）

> 2026-08-01 轉向台指期貨（ADR 0007）：核心決策（遊戲本體零 AI 依賴、複盤走戰報 .md 回 Claude Code）不變。預設三位大師陣容改為 Livermore／OPMAN／謝孟恭（Dalio 退居選配、林沖留給現股當沖版，見 SPEC v2.0 §6）；下文提及的 ADR 0004（地雷股）已廢止，相關敘述僅供歷史脈絡參考。

## 脈絡

遊戲核心迴圈（開局計畫矛盾偵測、進行中違背比對、即時介入）如果依賴 LLM，會綁上金鑰管理、網路延遲、API 成本與不可預測的輸出——這些都是「隨時想玩就能玩」的靜態網頁架構（ADR 0006）想避免的東西。但另一方面，賽後想要有真人教練等級的評語，這件事恰好是使用者已經蒸餾好的多位投資大師 perspective skill（Livermore、謝孟恭、Dalio 等）擅長的事，硬要在遊戲本體重造一遍沒有道理。

## 決策

把「當下要即時反應」與「事後要有深度評語」徹底切開（SPEC §7）：

- **遊戲本體零 AI 依賴**：矛盾偵測與中途介入全走規則＋預寫模板（見 ADR 0003），無金鑰、無網路、無延遲，離線也能玩。
- **複盤走戰報**：結算時輸出戰報 `.md`（開局計畫、逐筆交易與違背標記、違背統計、歷次對照曲線）到 `reports/`，玩家把這份檔案帶回 Claude Code，用 `/複盤` skill 觸發大師評語（M8）。
- **預設三位**：Livermore（停損執行/紀律）、謝孟恭（部位管理/凹單/心態）、Dalio（驅動因子分散/賭單一情境）。Buffett/Graham/Lynch 因為 v1 沒有基本面資料（ADR 0006）暫不上；林沖/OPMAN 留給台股版（ADR 0004）。

## 後果

- 換來遊戲本體零成本零依賴：可以純靜態部署，沒有 AI 服務掛掉導致遊戲玩不了的風險。
- 代價：賽後複盤不是即時的——玩家要主動離開瀏覽器、回到 Claude Code、餵戰報檔案進去，這是一個工作流斷點，不是遊戲內建的無縫體驗，需要在 UI 上明確引導（例如結算畫面提示「戰報已存到 reports/，回 Claude Code 跑 /複盤」）。
- 代價：**Buffett/Graham/Lynch 大師評語第一版無法上**——這三位的框架本質上依賴基本面資訊（護城河、內在價值、PEG），而 v1 明確砍掉基本面資料（ADR 0006），所以複盤陣容第一版只有技術面/行為面三位，不是完整的投資委員會體驗。
- 代價：`/複盤` skill 的品質完全綁定戰報 `.md` 的 schema——M7 如果之後調整戰報格式，M8 的 skill prompt 要同步改，這是遊戲輸出格式與 skill 之間的跨 repo（遊戲 repo vs `~/.claude/skills/`）耦合，交接時容易被漏掉，需要在 HANDOFF.md 持續提醒。
